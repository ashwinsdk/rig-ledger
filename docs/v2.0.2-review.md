# RigLedger v2.0.2 review

Release 2.0.2+7. Flutter app only (Android). Tasks T-J01 to T-J06 in `.claude/tasks/CURRENT.md`.

## Changes

| Item | Change |
|---|---|
| Bug 1: agent Save did nothing | Edit and Delete opened from the Portfolio agent sheet used the sheet's own context and ref after it had closed (`StateError`). The sheet now calls back into the Agents section. Adding an agent with custom prices was checked and works. |
| Bug 2: agent filter | The scrolling chip row is a pill "Agent: All agents" that opens a searchable list of every agent (also agents without bills) with bill count and total for the period. |
| Update 1: several lines per bill | `LedgerEntry.linesJson` (HiveField 38) holds lines of category depth, PVC or MS pipe with type, feet, rate and commission rate. The form lets you add and remove lines per category. Totals, step rate, commission, feet totals, filter, bill cards and exports use every line. Old bills load as one line per category. |

## Decisions (confirmed with the developer, 2026-10-20)

- Step rate is worked out per depth line, each line like its own entry (own type table, feet from 0). The bill step rate is the sum.
- Each line has its own commission rate, filled from the agent price of the line type (editable). Commission is never part of the total.
- The agent filter is a dropdown with search.

## Not asked, chosen

- Side bore bills have no types, so side bore lines only have feet, rate and commission rate.
- CSV and PDF type cells show `7inch + 8inch`. Feet columns are sums and the rate column is the average (amount / feet), so feet x rate still equals the amount. A per-line column was not added so existing import and export formats do not change.
- CSV import keeps one line per category.
- Lines with no feet and no rate are dropped for PVC and MS pipe when saving. Depth keeps at least one line.

## Data

Schema 7. Bills saved by 2.0.1 and older are read as before (lines are built from the single-type fields). A 2.0.2 snapshot is refused by older apps (higher schema), which protects the lines from being dropped.

## Tested

115 automated tests: lines model (compat, aggregates, per-line step rate, rename and usage in the database), form with two depth lines and PVC (total, commission, saved lines), side bore form with two lines, feet totals and CSV text, agent edit and delete from the sheet, the agent filter.

## Not tested

Anything on a device. The two form screens were only run as widget tests. Drive sync of bills with lines between two devices, PDF layout with long type text, and editing an old bill on 2.0.2 and opening it on 2.0.1 (refused by the schema check).
