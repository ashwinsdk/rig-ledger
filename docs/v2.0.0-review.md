# RigLedger v2.0.0 review: test result, bugs, improvements

Date: 2026-10-12. Scope: everything in `v2.0.0.md` plus the Account Ledger (cashbook replica).

## 1. How it was tested

Automated (all pass, `flutter test`): 68 tests in 16 files
- Calculation and logic: cashbook calculator (balances, periods, formats), expression evaluator, portfolio calculator, payment log and commission model maths, export builders (CSV, PDF incl. Tamil), import service with synthetic databases.
- Database and sync: providers with a real Hive database (books, entries, trash, 30 day purge, transfer, summaries, backup round trip), payment to receiver book link (12 tests, including vehicle deletion and reconcile), sync merge of the new collections (older snapshots without the new keys), a binary compatibility test (records written by pre-2.0.0 adapters load with safe defaults).
- Widgets: Account Ledger add, empty amount, delete and restore, search; About screen; new receiver payment dialog (crash regression).

On the Android emulator (debug build, by hand): Account Ledger add and list, hub drawer, Portfolio, side bore rig (no PVC, summary bar with Commission), agent with default commission, a main bore bill with depth, PVC and MS pipe (total 47,000 for depth 450 ft at 100 plus step rate 2,000, commission 900, payment of 20,000 received by a new receiver book "Ravi", balance 27,000), the receiver book showing Rs. 20,000, Portfolio profit 19,100 and expected profit 46,100, import from a real cashbook backup file (dry run, import, report).

NOT verified (be honest about the gaps)
- macOS app: `flutter build macos` fails here because `macos/Runner/GoogleService-Info.plist` (a secret that is not in the repo) is missing. Dart code was checked through `flutter analyze` and the macOS host test runs, not by running the .app. The macOS two-pane Account Ledger layout is therefore untested visually (one real bug in it was found by a test, see 3.1).
- Google Drive sign-in and a real two-device sync (needs accounts). Merge logic is unit tested only.
- Camera and gallery bill attachments, Android share sheet and file save dialogs for the new exports.
- Release builds and Play Store checks.

## 2. Decisions made while implementing (please confirm)

1. Commission = quantity in feet x rate per foot, for depth, PVC and MS pipe (`v2.0.0.md` examples "1000 x 2", "150 x 40", "100 x 60" were read as quantity x rate). Never added to total. If the meaning is different (for example a rate per 1000 ft), change `LedgerEntry.calculateCommission` and its test.
2. Profit = received - expenses - commission, plus "expected profit" = total - less - expenses - commission. Expenses are the side ledger purchases of the period. Expenses are not per agent, so profit is hidden when an agent filter is on.
3. The Stats tab became the Portfolio tab (Overview, Ledger, Side Ledger). Settings moved to tab 5 (Cmd+5 on macOS).
4. Old bills are not migrated: their received amount shows as "Earlier received" with no receiver.
5. The LICENSE copyright line uses the git author and first commit year (Ashwin Sudhakar, 2025-2026). The owner must confirm it. Governing law and a contact address were left out on purpose (not verifiable from the repo).
6. Backup and restore of the cashbook app's own .db is replaced by the normal RigLedger backup, Drive sync and the import tool. Excel export became CSV.

## 3. Bugs

### 3.1 Found and fixed in this release
| # | Bug | Fix |
|---|---|---|
| 1 | About dialog hardcoded "Version 1.0.7" and "Version: 7" while pubspec said 1.0.4+4 | About screen reads the version from the platform |
| 2 | Side bore: a newly added PhonePe name did not show in the dropdown until the bill was saved, so users thought it was not added | Payments are logged with a payer name field (autocomplete); old dropdown removed |
| 3 | Main bore address autocomplete re-attached a listener on every rebuild and reset the text (cursor jumps, leak) | Shared `AddressAutocompleteField` |
| 4 | Side bore bills and side ledger showed PVC although side bore has none | PVC hidden everywhere for side bore rigs |
| 5 | `test/widget_test.dart` did not compile (`MyApp`), so `flutter test` could not run at all | Replaced with a real smoke test |
| 6 | Deleting a vehicle left its bills and agents behind although the dialog says they are deleted (orphans kept syncing) | `DatabaseService.deleteVehicle` now deletes them (and trashes linked incomes) |
| 7 | Existing PDF reports used the default font, so Tamil addresses and notes were dropped | Bundled Noto Sans and Noto Sans Tamil |
| 8 | New code: disposing a dialog's TextEditingController right after `await showDialog` crashed with a red error screen (found on the emulator, new receiver dialog) | Controllers now live in the dialog State; regression test |
| 9 | New code: the macOS two-pane Account Ledger had InkWells without a Material ancestor (found by a widget test running on the macOS host) | Wrapped in a Scaffold |
| 10 | New code: restoring a linked income whose payment no longer exists would be trashed again at the next start | It becomes a normal income |

## 4. Improvements worth doing

Product
- Payment receipts: share a PDF receipt for a payment (bill number, amount, receiver, date).
- Per-rig and per-agent monthly statements from the Portfolio screen (PDF).
- Commission settlement: mark commission as paid to an agent and keep the balance (today it is informational only).
- Receiver books could show the bills they received money for (the link fields already exist).
- Notebook: reminders and a PDF report; recurring notes.
- Account Ledger: categories with totals, budgets per book, a "month closing" view.
- Import tool: import the Drive backup of the cashbook app and run a reconcile report (imported total vs source total).

Quality and UX
- Summary bar has four items and gets tight on small phones; use a two-row layout under 360 dp or compact numbers.
- Commission labels are truncated in the bill form on narrow widths ("Depth rate ..."); use a vertical layout under 380 dp.
- The Account Ledger drawer order could group reports and tools; the bottom label "Accounts" is easy to confuse with "Agents".
- Android back from the Settings tab leaves the app; add a back to Ledger tab step.
- The 5 tab bar on desktop could show the Portfolio and Account Ledger as sidebar sections with counts.
- Replace the bundled fonts' two TTF files (about 700 KB) with subsets if app size matters.
- Add `integration_test` to drive the emulator flows that were done by hand here (bill with payment and receiver, Portfolio numbers).
- Move remaining direct `DatabaseService` calls in widgets behind providers.

Security and privacy
- Encrypt the Hive boxes (`HiveAesCipher`) with a key from the platform keystore, or at least offer an app lock.
- Show the last Drive sync time and let users disconnect and delete the Drive file from Settings.
- Add a data export that includes the Account Ledger in one file (JSON backup already does).
